# 7.1 High-level design: context, containers, deployment

## Context

```mermaid
flowchart LR
  OWNER(["Owner<br/>(only user)"])
  BROWSER["Browser tab<br/>Chrome / Edge"]
  APP["OneNote Clone<br/>node server/index.js"]
  DISK[("Local disk<br/>data/")]
  SPEECH["Browser speech service<br/>(Dictate only)"]
  OWNER -->|"types, draws, clicks"| BROWSER
  BROWSER <-->|"HTTP JSON on 127.0.0.1:3000"| APP
  APP <-->|"SQLite + files"| DISK
  BROWSER -.->|"audio, only while Dictate is on"| SPEECH
```

**Why:** the only external dependency at runtime is optional. Dictation uses the browser's
built-in Web Speech API, which in Chrome sends audio to Google's speech service. Everything else
works offline. No CDN, no account, no sync service. See [../1_build-plan.md](../1_build-plan.md) §1.

## Containers

```mermaid
flowchart TB
  subgraph TAB["Browser tab"]
    FE["Frontend<br/>public/index.html + js/*.js<br/>ES modules, no build"]
    LS[("localStorage<br/>oc.* prefs")]
    FE --- LS
  end
  subgraph PROC["Node process (one)"]
    EXP["Express 5 app<br/>server/index.js"]
    SQL["node:sqlite<br/>DatabaseSync, WAL"]
    EXP --> SQL
  end
  subgraph DATA["DATA_DIR (default ./data)"]
    DB[("notes.db")]
    WAL[("notes.db-wal<br/>notes.db-shm")]
    UP[("uploads/<br/>uuid.ext")]
  end
  FE -->|"GET /, /js, /css (static)"| EXP
  FE -->|"/api/* JSON"| EXP
  FE -->|"GET /uploads/*"| EXP
  SQL --> DB
  SQL --> WAL
  EXP -->|"fs.writeFileSync"| UP
  BK["npm run backup<br/>scripts/backup.mjs"] -.->|"read-only VACUUM INTO"| DB
  TEST["npm test<br/>tests/*.test.mjs"] -.->|"spawns its own server<br/>(free port, temp DATA_DIR)"| EXP
  TEST -.->|"drives installed Chrome<br/>via playwright-core"| FE
```

**Why tests start their own server:** each suite gets a fresh database in the OS temp folder and
a free port, so `npm test` can run while the real server is up on 3000, and never touches
`data/`.

**Why:** one process owns the database, so there is no locking story to tell. `notes.db` and
`notes.db-wal` are drawn separately on purpose. Together they are the database, and on a small
notebook the WAL can hold everything (P8). The backup script is a separate short-lived process
that opens the DB read-only.

## Deployment

```mermaid
flowchart LR
  subgraph PC["Owner's Windows 10 PC"]
    CH["Chrome"]
    N["node server/index.js<br/>127.0.0.1:3000"]
    F[("D:/CODING/.../27_OneNoteClone/data")]
    CH -->|"loopback"| N --> F
  end
  PHONE["Phone / second device"]
  PROXY["Reverse proxy or Tailscale<br/>+ auth"]
  PHONE -.->|"PLANNED · OD4"| PROXY -.->|"PLANNED"| N
  classDef planned stroke-dasharray: 5 5
  class PHONE,PROXY planned
```

**Why:** bound to `127.0.0.1` because there is no authentication. The dashed path is not built.
It needs OD4 (how to protect it) and OD3 (two devices editing one page) settled first.
