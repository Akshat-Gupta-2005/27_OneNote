# 7.5 State machines

## Save status (the title-bar indicator)

Values are the strings `PageEditor` emits as `status` events.

```mermaid
stateDiagram-v2
  [*] --> saved : load(page)
  saved --> dirty : scheduleSave()
  dirty --> dirty : more input (timer restarts)
  dirty --> saving : timer fired, snapshot changed
  dirty --> saved : timer fired, snapshot unchanged
  saving --> saved : 200 and no timer pending
  saving --> dirty : input while in flight (scheduleSave)
  saving --> error : network error / 5xx
  error --> saving : retry after 4 s
  error --> dirty : user keeps typing (scheduleSave)
```

**Why it matters:** the toast fires on the first `error` after a `saved`, not on every entry into
`error`. Each retry passes through `saving → error`, and the earlier version toasted every time
(P7).

## Page lifecycle

```mermaid
stateDiagram-v2
  [*] --> live : POST /api/pages (or new section / notebook)
  live --> trashed : DELETE /api/pages/{id} → deleted_at = now
  trashed --> live : POST /restore → deleted_at = NULL
  trashed --> [*] : DELETE ?permanent=1, DELETE /api/trash, or purge after 60 days
  live --> [*] : section or notebook deleted (cascade)
  trashed --> [*] : section or notebook deleted (cascade)
```

**Why the cascade edges matter:** deleting a section also destroys its trashed pages. The trash
does not protect them (contract obligation 6).

## Editor tool mode

```mermaid
stateDiagram-v2
  [*] --> type
  type --> pen : modePen
  type --> hl : modeHl
  type --> eraser : modeEraser
  pen --> hl : modeHl
  hl --> pen : modePen
  pen --> eraser : modeEraser
  hl --> eraser : modeEraser
  eraser --> pen : modePen
  eraser --> hl : modeHl
  pen --> type : Esc / modeType / load(page)
  hl --> type : Esc / modeType / load(page)
  eraser --> type : Esc / modeType / load(page)
```

In any mode other than `type`, the ink SVG takes pointer events (class `draw` on `#pageInner`), so
containers cannot be clicked. Opening another page always returns to `type`. A pen's eraser end
(`pointerdown` with `button === 5`) erases even in `pen` mode.

## Planner add box (since 2026-10-17)

One per page view (`openAdd` in `todo.js`). Never stored.

```mermaid
stateDiagram-v2
  [*] --> closed
  closed --> open : click + (or title Enter / ↓ for the first group)
  open --> open : Enter with text → task added, box cleared
  open --> open : click another group's + (that box opens instead)
  open --> closed : Esc (focus → +)
  open --> closed : blur while empty, after the click lands
  open --> open : blur with text (kept)
```

**Why "after the click lands":** focus leaves on `pointerdown`; removing the box then would shift
the rows below it before `pointerup`, and the click would miss (decisions, 2026-10-17).

## Card due badge (since 2026-10-17)

Computed by `dueState()` in `board.js` on every render, from `due`, `dueDone` and today's date.

```mermaid
stateDiagram-v2
  [*] --> none : due = null
  none --> later : set due beyond tomorrow
  none --> soon : set due today or tomorrow
  later --> soon : days pass
  soon --> overdue : due date passes
  later --> done : dueDone = true
  soon --> done : dueDone = true
  overdue --> done : dueDone = true
  done --> later : dueDone = false (future date)
  done --> overdue : dueDone = false (past date)
```

Clearing the due date returns any state to `none` (edges omitted for legibility). Badge colors:
`overdue` red, `soon` yellow, `done` green, `later` plain. **Why a state machine
here:** four values, and the date-driven edges (`later → soon → overdue`) happen without any edit,
so a stored status would go stale. The state is never stored.
